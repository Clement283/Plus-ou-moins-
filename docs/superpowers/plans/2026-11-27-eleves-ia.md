# Élèves IA — plan de construction

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**But :** faire tester un cours (ou un module) par 3 élèves IA et un prof de maths IA, à partir d'une version texte du cours, et produire un rapport par cours.

**Architecture :** des scripts TypeScript dans `scripts/eleves/` (lancés avec `tsx`, testés par Vitest via `npm test`) écrivent le cours en texte, préparent les connaissances des élèves, mesurent le dosage et corrigent les réponses avec le moteur `@pom/engine`. Une skill de projet orchestre : elle lance les scripts, les 4 sous-agents (Sonnet), l'aller-retour des corrections, puis écrit et commite les rapports.

**Technique :** TypeScript, `tsx`, Vitest, `@pom/engine` (`courseRunItems`, `checkAnswer`, `feedbackFor`, `feedbackText`, juges `judgeValues`/`judgeLabels`/`judgeSigns`), outil Agent + SendMessage.

**Spec :** `docs/superpowers/specs/2026-11-27-eleves-ia-design.md`

## Contraintes globales

- Rapport seulement : la skill ne modifie **jamais** un cours ; correction après le go de Clément, via `plus-ou-moins-ecrire-un-cours`.
- Le fichier donné à un élève ne contient **jamais** les bonnes réponses ni les messages d'erreur.
- L'élève ne lit **jamais** les fiches ; le prof les lit.
- Part retenue des points des cours précédents : fort **90 %**, moyen **50 %**, faible **25 %** (+ bases du collège, erreurs de signes) ; tirage avec une graine notée dans le rapport.
- Messages d'erreur : à la **fin de chaque cours** (option B) ; l'élève dit si le message l'aide, puis réessaie une fois.
- Sous-agents élèves et prof : modèle **Sonnet**.
- Repère de dosage : moyenne de **tous** les cours existants (`MODULES` + `ESSAIS`), recalculée à chaque lancement.
- Rapports : `docs/modules/NN-nom/tests/<cours>-AAAA-MM-JJ.md`, plus `module-AAAA-MM-JJ.md` pour un module ; commités.
- Textes en français ; « − » U+2212 comme dans les cours.
- Scripts sans réseau ; fichiers de travail d'un lancement dans le scratchpad de la session (pas dans le dépôt).

## Points à surveiller en revue

1. **Réponse d'élève mal formée** (« x vaut 3 », « 3. », « −3 » avec tiret ASCII, choix « B » au lieu de « 2 ») : `corriger` doit accepter les variantes courantes (tiret ASCII → « − », espaces, lettre de choix) et, sinon, renvoyer `{ convertie: false }` avec le message général — jamais planter. Test dans la tâche 3.
2. **Question d'un type non géré** (nouveau `kind` ajouté plus tard) : `questionTexte` et `versReponse` lèvent une erreur claire qui nomme le `kind` ; un test parcourt **tous** les cours existants et vérifie qu'aucun écran ne la lève. Tests dans les tâches 1 et 3.
3. **Cours sans fiche** (c00 à c03 n'ont que du code) : `pointsDuCours` retombe sur `course.rule` et `memo.ruleBullets`. Test dans la tâche 2.
4. **Fuite de réponse dans le fichier élève** : un test vérifie que le texte élève de chaque cours ne contient aucune ligne de `cles` (bonne réponse, message). Test dans la tâche 1.
5. **Tirage reproductible** : même graine ⇒ mêmes exercices de fin et mêmes points retenus ; graine différente ⇒ tirage différent. Tests dans les tâches 1 et 2.

### Tâche 1 : le cours en texte

**Fichiers :**
- Créer : `scripts/eleves/rendu.ts` (texte d'un bloc, d'une question, d'une étape)
- Créer : `scripts/eleves/ecrans.ts` (le cours entier en écrans)
- Test : `scripts/eleves/ecrans.test.ts`

**Interfaces :**
- Consomme : `getCourse`, `courseRunItems`, `seededRng` de `@pom/engine`.
- Produit :
  ```ts
  export interface Ecran {
    n: number;                       // 1, 2, 3… dans l'ordre du cours
    titre: string;
    texte: string;                   // ce que l'élève voit, sans réponse
    question?: { format: string };   // comment répondre (« un nombre », « le numéro du choix », « tes lignes de calcul, une par ligne »…)
  }
  export interface Cle {             // gardé par l'orchestrateur, jamais montré à l'élève
    n: number;
    itemId: string;                  // ActivityItem.itemId, ou `${itemId}#etape-${k}` pour une étape à action
    bonneReponse: string;
  }
  export interface CoursTexte { courseId: string; titre: string; ecrans: Ecran[]; cles: Cle[] }
  export function coursEnTexte(courseId: string, graine: number): CoursTexte;
  export function ecransEnMarkdown(c: CoursTexte): string;   // « ## Écran 3 — titre », texte, « Réponds par : … »
  // rendu.ts
  export function blocTexte(b: LessonBlock): string;
  export function questionTexte(q: Question): { texte: string; format: string; bonneReponse: string };
  ```

Rendu : un item `explication` = un écran (blocs, ou étapes : une étape par paragraphe ; une étape avec `action` autre que `comprends` devient sa propre question, choix numérotés pour `trou`, graduations/indices listés pour `graduation`/`morceau`/`endroit`) ; `autres` = recap + techniques en texte ; chaque item `question` = un écran. Blocs `math` : LaTeX laissé tel quel ; `number-line` et `anim` : une ligne entre crochets (« [droite graduée de −5 à 5 : saut de +3 depuis −2] », « [animation : nom] »). Choix numérotés à partir de 1. Textes de `PartTexts` (title, subtitle, consigne, intro, outro) inclus.

### Tâche 3 : corriger avec le moteur

**Fichiers :**
- Créer : `scripts/eleves/corriger.ts`
- Test : `scripts/eleves/corriger.test.ts`

**Interfaces :**
- Consomme : `coursEnTexte`, `Cle` (tâche 1) ; `checkAnswer`, `feedbackFor`, `feedbackText`, `judgeValues`, `judgeLabels`, `judgeSigns`, `tableauSolution` de `@pom/engine`.
- Produit :
  ```ts
  export interface Correction { n: number; juste: boolean; convertie: boolean; message: string; bonneReponse: string }
  export function versReponse(q: Question, reponse: string, expectInteger: boolean): Answer | null;
  export function corriger(courseId: string, graine: number, n: number, reponse: string): Correction;
  ```

Conversion texte → `Answer` (une réponse = une chaîne ; plusieurs lignes séparées par des retours à la ligne) :

| kind | texte de l'élève | Answer |
|---|---|---|
| saisie, trou | un nombre | `{ raw }` (touches comme au clavier de l'appli, `pressKey`) |
| droite | un nombre | `{ point }` |
| qcm, choix | numéro (ou lettre A, B…) | `{ choice: numéro − 1 }` |
| vraifaux | vrai / faux | `{ bool }` |
| erreur | numéro de ligne ou « tout est juste » | `{ line: numéro − 1 \| null }` |
| reecrire | l'écriture | `{ text }` |
| ordre | numéros dans l'ordre | `{ order }` |
| paires, classer | « 1-3, 2-1 » / une classe par ligne | `{ pairs }` / `{ classes }` |
| resoudre | lignes d'équation | `{ lines, hinted: false }` |
| calculer | lignes de calcul | `{ calcLines, firstPick: true, hinted: false }` |
| intervalle | « ]−∞ ; 3[ » (et « ∪ … ») | `{ interval, interval2, symbol, hinted: false }` |
| solutions | valeurs séparées par « ; » | `{ values, hinted: false }` |
| tableau | 3 parties : valeurs, libellés, signes ligne par ligne | `{ tableau: errorIds, hinted: false }` via les juges |

Étape à action (`#etape-k`) : `trou` → message `errors[choix]` ; `graduation`/`morceau`/`endroit` → `StepFault` dont `at` correspond, sinon `fallback`. Normalisation commune : tiret ASCII et « – » → « − », espaces superflus, virgule décimale. Message = `feedbackText(feedbackFor(...))`, plus le texte de `explanation` (règle + étapes) quand il existe. Réponse non convertible → `{ convertie: false, juste: false, message: <message général du cours pour cette question> }`.

### Tâche 4 : la ligne de commande

**Fichiers :**
- Créer : `scripts/eleves/cli.ts`
- Test : `scripts/eleves/cli.test.ts`

**Interfaces :**
- Consomme : tout ce qui précède.
- Produit deux commandes (utilisées par la skill) :
  ```bash
  npx tsx scripts/eleves/cli.ts preparer <courseId|NN-dossier-module> --dossier <dir> [--graine <n>]
  npx tsx scripts/eleves/cli.ts corriger --dossier <dir> <courseId> <reponses.json>
  ```
  `preparer` écrit dans `<dir>` : `ecrans-<id>.md` (élève), `cles-<id>.json`, `connaissances-<profil>.md` (retenus, pour le 1er cours testé), `oublies-<profil>.json`, `mesures.json` (`{ cours: Mesure[], moyenne }`), `lancement.json` (`{ cours: string[], graine, date }`). Graine par défaut : `Date.now() % 100000`, écrite dans `lancement.json`.
  `corriger` lit `reponses.json` (`[{ n, reponse }]`) et écrit sur la sortie standard `Correction[]` en JSON.
  Export testable : `export function preparer(cible: string, dossier: string, graine: number): void` et `export function corrigerFichier(dossier: string, courseId: string, reponses: { n: number; reponse: string }[]): Correction[]`.
